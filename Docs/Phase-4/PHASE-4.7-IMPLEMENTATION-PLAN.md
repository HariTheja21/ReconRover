# Phase 4.7: ESP32 UART Integration Layer - Implementation Plan

## Executive Summary
Phase 4.7 completes the ESP32 software backbone by implementing the physical UART Integration Layer. This module acts as the two-way bridge connecting the FreeRTOS Runtime Core (receiving motor/servo commands) and the Telemetry System (transmitting hardware states) to the ESP-IDF hardware UART driver. It abstracts hardware interrupts, ring buffers, and physical byte flushing away from logical robot operations.

## Objectives
- Implement `UartManager` to initialize ESP-IDF UART drivers and provide a tick-based processing loop.
- Implement `UartEngine` to orchestrate RX byte parsing and TX queue flushing.
- Implement `UartReceiver` as a strict state machine to identify `0xAA55` headers, frame 9-byte payloads, validate CRC8, and dispatch complete packets upward to the Runtime Core.
- Implement `UartTransmitter` as a non-blocking queue to hold Telemetry packets until the RTOS tick can push them to hardware.
- Implement `UartBuffer`, a $O(1)$ static ring buffer template to securely hold bytes in transit without dynamic heap allocation.

## Architecture
- `ESP32_ROVER/main/uart/uart_events.h`: Standard 9-byte struct definition.
- `ESP32_ROVER/main/uart/uart_buffer.h`: Static ring buffer.
- `ESP32_ROVER/main/uart/uart_receiver.cpp`: Framer state machine.
- `ESP32_ROVER/main/uart/uart_transmitter.cpp`: Output queuing.
- `ESP32_ROVER/main/uart/uart_engine.cpp`: Logic binding.
- `ESP32_ROVER/main/uart/uart_manager.cpp`: Hardware initialization and RTOS hooks.

## FreeRTOS Considerations
- **ISR Safety:** Incoming bytes generated by the UART hardware interrupt will immediately feed the `UartReceiver` state machine. This state machine is mathematically constrained (constant time) to execute safely within an ISR context without blocking RTOS execution.
- **Zero Allocation:** The `UartBuffer<256>` is allocated statically at compile time, eliminating heap fragmentation on the microcontroller.
- **Non-Blocking TX:** Telemetry packets are placed into the `UartTransmitter` buffer. The `Tick()` function dequeues bytes and writes them to the hardware driver sequentially, preventing the telemetry task from stalling during slow baud rate transmissions.

## Error Recovery
- The `UartReceiver` is designed to aggressively recover from framing errors. If a false `0xAA` is received, but not followed by `0x55`, the state machine instantly resets, ready to catch the next valid header sequence without requiring external reset logic.
