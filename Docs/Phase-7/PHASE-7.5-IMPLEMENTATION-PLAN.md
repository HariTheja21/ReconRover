# Phase 7.5: Semantic Mapping Engine - Implementation Plan

## Executive Summary
Phase 7.5 introduces the Semantic Mapping Engine into the AI Runtime Framework. This module is responsible for persisting the ephemeral 3D objects generated by the Perception Engine into a long-term, queryable spatial database (`SQLite`). It builds a `KnowledgeGraph` of the environment, links entities across time, and infers high-level spatial classifications (e.g., determining a zone is a "bedroom" because it contains a bed). This grants the rover long-term spatial memory, enabling complex future commands like "Go to the kitchen".

## Objectives
- Build `SemanticRuntime` and `SemanticManager` as the core orchestrators for semantic memory.
- Implement `PersistentStorage` (SQLite) and `SemanticDatabase` to securely save object classes and `[x,y,z]` coordinates to disk.
- Develop `ObjectMemory` and `SceneMemory` to manage the ingestion of live data from the Perception Engine.
- Construct `EntityLinker` to handle object permanence across time, ensuring the same physical chair is not duplicated in the database.
- Build `RoomClassifier` to apply semantic labels to geographic zones based on their constituent objects.
- Create `KnowledgeGraph` and `LandmarkManager` to map the relationships between objects, rooms, and user-defined landmarks.
- Ensure strict EventBus integration via `SemanticBridge`.

## Architecture
- **Ingestion Pipeline:** SceneUpdated -> `SceneMemory` -> `EntityLinker` -> `ObjectMemory` (SQLite) & `KnowledgeGraph`.
- **Classification Pipeline:** Analyzes objects in the current zone -> `RoomClassifier` -> Emits `RoomClassified` event.
- **Event Routing:** The `SemanticBridge` emits `SemanticMapUpdated` and `RoomClassified` to the `semantic.map` and `semantic.spatial` topics respectively.

## Safety & Constraints
- **Asynchronous Scheduler:** The `SemanticScheduler` uses bounded `asyncio.Queue` structures to process scene and landmark updates without blocking the main event loop.
- **Thread Safety:** The SQLite connection relies on `check_same_thread=False` but executes all write operations sequentially within the `run_scene_loop` async worker, preventing database locks.
